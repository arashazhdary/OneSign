Step 4: Domain services – PolicyDefinition & Evaluation

Implement IPolicyDefinitionService:

- Responsible for:
  - Creating/updating/deleting PolicyDefinition with its ConditionGroups and Conditions.
  - Validating Conditions:
    - Non-empty ConditionGroups.
    - Valid operators per AttributeSourceType.
  - Managing assignments:
    - AssignPolicyToTarget.
    - UnassignPolicyFromTarget.
    - ReorderPolicyDefinitions per target.

Implement IPolicyEvaluationService:

Define:

```csharp
public sealed class PolicyEvaluationContext
{
    public Guid TenantId { get; init; }

    public string UserId { get; init; }
    public IReadOnlyCollection<string> UserRoles { get; init; }
    public IReadOnlyDictionary<string, string> UserClaims { get; init; }
    public IReadOnlyCollection<string> OrgUnitCodes { get; init; }

    public string ClientId { get; init; }
    public IReadOnlyCollection<string> RequestedScopes { get; init; }

    public string RiskLevel { get; init; }   // e.g. Low, Medium, High
    public double? RiskScore { get; init; }  // optional numeric score
}


Decision result:

public sealed class PolicyDecision
{
    public bool IsAllowed { get; init; }
    public IReadOnlyCollection<string> AllowedScopes { get; init; }
    public string DeniedReasonCode { get; init; }
    public IReadOnlyCollection<Guid> MatchedPolicyIds { get; init; }
}


Behavior:

If PolicyEngineEnabled == false for this tenant:

Fall back to existing RBAC logic:

Determine allowed scopes using the existing role-based rules.

Return IsAllowed/AllowedScopes accordingly.

If PolicyEngineEnabled == true:

Resolve PolicyTargets relevant for this context:

For application: TargetType = Application, TargetKey = ClientId.

For scopes: TargetType = Scope, TargetKey in RequestedScopes (and combine).

Load PolicyAssignments for relevant targets (ordered by Order/Priority).

Evaluate policies:

For each PolicyDefinition in order:

Evaluate ConditionGroups:

A group is true if its Conditions combine according to its LogicalOperator (AND/OR).

A PolicyDefinition matches if ANY of its ConditionGroups is true.

For each Condition:

Resolve value from context based on AttributeSourceType and SourceKey:

UserRole: roles collection.

OrgUnit: orgUnitCodes.

UserClaim: from UserClaims dictionary.

RiskContext: RiskLevel or RiskScore.

Client: ClientId or client properties.

Apply ConditionOperator (Equals, In, etc.).

When evaluating effect:

Deny overrides Allow.

Recommended behavior:

Collect matching Deny and Allow policies.

If any Deny matches → IsAllowed = false.

Otherwise if any Allow matches → IsAllowed = true.

If none matches → fall back to RBAC baseline.

Compute AllowedScopes:

If Deny:

AllowedScopes may be empty.

If Allow:

AllowedScopes should be a subset of RequestedScopes consistent with RBAC and matching policies.

Return PolicyDecision:

IsAllowed

AllowedScopes

DeniedReasonCode (message code, not raw string).

MatchedPolicyIds (for observability/testing).

Add caching:

Cache PolicyDefinitions/Assignments per tenant in-memory with invalidation when policies change.

Ensure evaluation path is efficient for high RPS (no N+1 queries).
