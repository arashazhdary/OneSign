2) Instance-side scheduler

- Reads EnvironmentId and Endpoint from config.
- Every N minutes:
  - builds EnvironmentHeartbeatRequest
  - POST to /api/environment/heartbeat (or internal if registry is same instance).
- Ensure:
  - no TODO / empty implementation; heartbeat really calls into API.

Status derivation:

- Later, in UI or helper:
  - Status = Healthy if LastHeartbeatAt < threshold (e.g. 10 min)
  - Stale / Down otherwise.

Step 5: Implement EnvironmentBootstrapService
--------------------------------------------------

Service interface:

- IEnvironmentBootstrapService
  - Task BootstrapAsync(DeploymentDescriptor descriptor)

Implementation:

1) Validate descriptor:
   - If invalid, throw a clear domain exception with validation error list.

2) Create or update Environment:

   - If Environment with descriptor.Environment.Id exists:
     - update Name, Type, RegionId, BaseUrl.
   - Else:
     - create new Environment with:
       - Id = descriptor.Environment.Id
       - Name, Type, RegionId, BaseUrl
       - LicenseKey = descriptor.License.Key (encrypted/secured)
       - AppVersion = current application version
       - DbSchemaVersion = current migration version
       - CreatedAt = now

3) Persist config:

   - Use your global configuration mechanism to store:
     - database connection string(s)
     - storage endpoints
     - smtp config
     - observability endpoints
     - feature flags

4) Initialize/migrate DB:

   - If DB schema for this environment is empty:
     - run initial migrations.
   - Else:
     - run migrations to latest.
   - Update Environment.DbSchemaVersion with actual schema version.

5) Feature configuration:

   - Create/update EnvironmentFeatureConfig for this Environment:
     - EnabledModules based on descriptor.Features.
     - Optionally default MaxTenants/MaxUsers if license is simple.

Bootstrap API:

- POST /api/global/environments/bootstrap
  - Accepts raw YAML or JSON descriptor.
  - Steps:
    - Parse → DeploymentDescriptor
    - Validate
    - Call BootstrapAsync.

Authorization:
- Only Global Admin / SRE.

Audit:
- Emit:
  - "Environment.BootstrapStarted"
  - "Environment.BootstrapCompleted"
  - "Environment.BootstrapFailed"

--------------------------------------------------

1) Data model

Either:

- Extend Environment with:
  - LicenseKey
  - MaxTenants

or:

- Separate table EnvironmentFeatureConfig:
  - EnvironmentId (PK)
  - MaxTenants
  - MaxUsers
  - MaxApplications
  - EnabledModules (json or table)

Implement EF mapping and migration.

2) FeatureGate service

Interface:

- IFeatureGate
  - bool IsEnabled(string moduleKey)

Implementation:

- Load EnvironmentFeatureConfig for current Environment (from cache).
- Example module keys:
  - "Module.Federation"
  - "Module.Governance"
  - "Module.DevPortal"
  - "Module.Extensibility"
  - "Module.IdentityLifecycle"
  - "Module.AdaptiveSecurity"

Usage:

- In startup:
  - Only wire routes / services for disabled modules if you want them soft-disabled, or keep them but enforce gating at entrypoints.
- In business logic:
  - Before actions like:
    - enabling Federation config,
    - creating Governance campaigns,
    - enabling Extensibility,
    - check IsEnabled.

3) Limit enforcement

- When creating tenants:
  - Count existing tenants for this Environment.
  - If MaxTenants>0 and count >= MaxTenants:
    - throw a domain exception: license limit reached.
- Similarly for users and applications if you want to enforce.
