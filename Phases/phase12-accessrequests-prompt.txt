Step 4: Core services - AccessRequestService and ApprovalService

Implement IAccessRequestService

Methods:

- `Task<AccessRequestDto> CreateRequestAsync(Guid tenantId, string requestorUserId, CreateAccessRequestRequest request)`
  - Creates a new AccessRequest with:
    - Status = Submitted
    - Items created for each requested Application or Role
    - RequestorDisplayName resolved from user profile service
  - For each item:
    - Call WorkflowEngine.StartWorkflowAsync(requestId, itemId)
  - Emit audit event "AccessRequest.Submitted"
  - Emit Notification via NotificationCenter (Phase 11) for event type "AccessRequest.Submitted".

- `Task<IReadOnlyList<AccessRequestDto>> GetMyRequestsAsync(Guid tenantId, string requestorUserId, ...)`
  - Returns requests limited to that user.

- `Task<AccessRequestDto> GetRequestDetailsAsync(Guid tenantId, Guid requestId, string currentUserId, bool isAdminOrOwner)`
  - Enforce that:
    - Requestor can see own requests.
    - Tenant admins and governance roles can see tenant requests.

- `Task CancelRequestAsync(Guid tenantId, Guid requestId, string requestorUserId)`
  - Only if Status is Submitted or InProgress.
  - Set Status = Cancelled and CompletedAt = now.
  - Audit "AccessRequest.Cancelled".

Implement IAccessApprovalService

Methods:

- `Task<IReadOnlyList<AccessApprovalInstanceDto>> GetApproverWorklistAsync(Guid tenantId, string approverUserId, ...)`
  - Returns all approval instances where:
    - Status = Pending
    - Current step is assigned to this approver.

- `Task ApproveAsync(Guid tenantId, Guid approvalInstanceId, string approverUserId, string reason)`
- `Task RejectAsync(Guid tenantId, Guid approvalInstanceId, string approverUserId, string reason)`
- `Task EscalateAsync(Guid tenantId, Guid approvalInstanceId, string approverUserId, string reason)`

Behavior:

- Validate that current approverUserId is allowed to act on this step.
- Append an AccessApprovalDecision record.
- Call WorkflowEngine.AdvanceOnApprovalAsync(approvalInstanceId, decision).

Step 5: Workflow Engine and Provisioning
--------------------------------------------------

Implement IAccessRequestWorkflowEngine

Methods:

- `Task StartWorkflowAsync(Guid tenantId, Guid requestId, Guid requestItemId)`
  - Determine the appropriate AccessApprovalFlow:
    - If there is a flow matching (TenantId, TargetType, ApplicationClientId or RoleName and IsEnabled) use it.
    - If none found, use a default flow if defined, or treat as auto approved (based on Phase 12 spec).
  - Create AccessApprovalInstance with:
    - Status = Pending
    - CurrentStepOrder = first step
  - Identify the first approver(s) based on AccessApprovalStepType:
    - Manager: use OrgHierarchy and manager of the requestor's OrgUnit.
    - AppOwner: use Application module metadata.
    - SecurityOfficer: use security role or group in tenant.
    - CustomRole: use users in that role.
  - Emit Notification via NotificationCenter:
    - Event type such as "AccessRequest.StepPending" to assigned approver(s).

- `Task AdvanceOnApprovalAsync(Guid tenantId, Guid approvalInstanceId, AccessApprovalDecision decision)`
  - If decision.Status is Rejected:
    - Mark AccessApprovalInstance.Status = Rejected.
    - Mark the related AccessRequestItem as IsRejected = true.
    - If all items in the parent AccessRequest are rejected:
      - Set AccessRequest.Status = Rejected, CompletedAt = now.
    - Emit audit "AccessRequest.StepRejected" and "AccessRequest.Rejected".
    - Notify requestor via NotificationCenter with "AccessRequest.Rejected".
  - If decision.Status is Approved:
    - If there is a next step:
      - Update CurrentStepOrder to next.
      - Emit Notification to the next step's approver(s).
    - If this was the last step:
      - Mark AccessApprovalInstance.Status = Approved.
      - Mark AccessRequestItem.IsApproved = true.
      - Call IAccessRequestProvisioningService for this item.
      - If all items in the parent AccessRequest are approved and provisioning succeeded:
        - Set AccessRequest.Status = Approved, CompletedAt = now.
      - Emit audit "AccessRequest.StepApproved" and "AccessRequest.Completed".
      - Notify requestor via NotificationCenter with "AccessRequest.Approved".
  - If decision.Status is Escalated:
    - Apply escalation policy:
      - For example, assign to SecurityOfficer or a higher role.
    - Update ApprovalInstance appropriately and notify new approver.
    - Audit "AccessRequest.StepEscalated".

Implement IAccessRequestProvisioningService

Method:

- `Task ProvisionAsync(Guid tenantId, AccessRequest request, AccessRequestItem item)`

Behavior:

- If item.TargetType = Application:
  - Use PolicyEngine and role module to assign appropriate role or permission that grants access to that application for the user.
- If item.TargetType = Role:
  - Directly assign that role to the user using Authorization or UserRole services.
- If the assignment must be propagated to external systems:
  - Emit an event or call Federation or SCIM module so target systems get updated.
- On success:
  - Audit "AccessRequest.ProvisioningSucceeded".
- On failure:
  - Mark AccessRequest.Status = Failed or mark item as failed with error information.
  - Audit "AccessRequest.ProvisioningFailed".
  - Notify TenantAdmin or SecurityOfficer via NotificationCenter.

Step 6: Backend APIs
--------------------------------------------------

Account side APIs (end user) under `/api/account/access-requests`

All account APIs must be scoped to the current user as requestor.

- `GET /api/account/access-requests/catalog`
  - Returns a list of AccessRequestCatalogItemDto with:
    - Resource type: Application or Role.
    - ApplicationClientId and Name, Description.
    - RoleName and Description, Sensitivity level.
  - Only include items that are requestable and allowed for this user based on tenant configuration.

- `GET /api/account/access-requests/my`
  - Returns paged list of AccessRequestDto for the current user.

- `GET /api/account/access-requests/{id}`
  - Returns details of a specific AccessRequestDto, including its items and approval status.

- `POST /api/account/access-requests`
  - Body: CreateAccessRequestRequest:
    - Items: list of targets (ApplicationClientId or RoleName).
    - Justification (required).
  - Calls IAccessRequestService.CreateRequestAsync.
  - Returns created AccessRequestDto.

- `POST /api/account/access-requests/{id}/cancel`
  - Cancels the given request if status allows.
  - Only the original requestor can cancel.
  - Calls CancelRequestAsync.

Tenant side APIs (flows, approvals, dashboard) under `/api/tenant/access-requests`

Flows API

- `GET /api/tenant/access-requests/flows`
  - Returns list of AccessApprovalFlowDto for the tenant.

- `GET /api/tenant/access-requests/flows/{id}`
  - Returns full details including step definitions.

- `POST /api/tenant/access-requests/flows`
  - Body: CreateAccessApprovalFlowRequest:
    - TargetType (Application or Role).
    - ApplicationClientId or RoleName.
    - Steps with StepType, CustomRoleName, AllowDelegate, AutoApproveIfNoOwner.
  - Creates a new flow.

- `PUT /api/tenant/access-requests/flows/{id}`
  - Body: UpdateAccessApprovalFlowRequest.
  - Allows updating steps and enabling or disabling flow.

- `DELETE /api/tenant/access-requests/flows/{id}`
  - Disables or removes flow based on your global design policy (soft delete recommended).

Approvals API

- `GET /api/tenant/access-requests/approvals/my`
  - Returns worklist of AccessApprovalInstanceDto for the current user as approver.
  - Filters only pending steps assigned to this user.

- `POST /api/tenant/access-requests/approvals/{approvalInstanceId}/approve`
  - Body: ApprovalDecisionDto with Reason.
  - Calls IAccessApprovalService.ApproveAsync.

- `POST /api/tenant/access-requests/approvals/{approvalInstanceId}/reject`
  - Body: ApprovalDecisionDto with Reason.
  - Calls IAccessApprovalService.RejectAsync.

- `POST /api/tenant/access-requests/approvals/{approvalInstanceId}/escalate`
  - Body: ApprovalDecisionDto with Reason.
  - Calls IAccessApprovalService.EscalateAsync.

Dashboard API

- `GET /api/tenant/access-requests/dashboard`
  - Returns AccessRequestDashboardStatsDto including:
    - Total requests in the last N days.
    - Pending requests.
    - Approved requests.
    - Rejected requests.
    - Overdue approvals (based on SLA).
    - Optional average approval time.

All tenant APIs must be tenant scoped and enforce proper roles:
- TenantAdmin, GovernanceOfficer, SecurityOfficer where needed.
- Approver endpoints must ensure the current user is the assigned approver for that step.
