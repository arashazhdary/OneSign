Step 5: Account APIs under `/api/account/*`

All endpoints must:

- Use current authenticated user as context.
- Use tenant context from token (TenantId).
- Never allow cross user access.

Profile

- GET `/api/account/profile`
  - Returns AccountProfileDto for (tenantId, userId).
- PUT `/api/account/profile`
  - Body: UpdateAccountProfileRequest.
  - Updates display name, language, timezone and avatar url if present.

Security

- POST `/api/account/security/change-password`
  - Body: ChangePasswordRequest with CurrentPassword, NewPassword, ConfirmPassword.
  - Validates and updates password via IAccountSecurityService.

- GET `/api/account/security/mfa-methods`
  - Returns list of MfaMethodDto describing active and available methods.

- POST `/api/account/security/mfa/totp/setup`
  - Starts TOTP setup flow, returning QR code data and secret (DTO to be defined).
- POST `/api/account/security/mfa/totp/confirm`
  - Confirms TOTP code and activates TOTP.
- DELETE `/api/account/security/mfa/totp`
  - Removes the TOTP method for this user.
- POST `/api/account/security/mfa/recovery-codes/regenerate`
  - Regenerates recovery codes and returns them once.

Devices and sessions

Devices:

- GET `/api/account/devices`
  - Returns list of UserDeviceDto for this tenant and user.
- DELETE `/api/account/devices/{deviceId}`
  - Removes the given device or trust state for this user.
- DELETE `/api/account/devices`
  - Removes all trusted devices for this user.

Sessions:

- GET `/api/account/sessions`
  - Returns list of UserSessionDto from ISessionOverviewService.
- DELETE `/api/account/sessions/{sessionId}`
  - Terminates the given session if it belongs to this user.
- DELETE `/api/account/sessions`
  - Terminates all sessions for this user except current session.

Activity

- GET `/api/account/activity`
  - Query parameters:
    - from (optional)
    - to (optional)
  - Uses Observability module (AuditEvents) to return UserActivityEntryDto for:
    - ActorId = current user
    - Categories Auth and Security
  - Paginate results.

Consents

- GET `/api/account/consents`
  - Returns list of UserConsentDto with:
    - ApplicationName
    - ClientId
    - GrantedScopes
    - GrantedAt
    - LastUsedAt

- POST `/api/account/consents/{id}/revoke`
  - Calls IConsentService.RevokeConsentAsync.
  - Also revokes associated refresh tokens.
  - Creates an audit event "Account.Consent.Revoked".

Recovery and notifications

- GET `/api/account/recovery-options`
  - Returns UserRecoveryOptionDto list.
- PUT `/api/account/recovery-options`
  - Body: UpdateRecoveryOptionsRequest.
  - Updates email and phone and triggers verification flows.

- GET `/api/account/notification-preferences`
  - Returns NotificationPreferenceDto list for each event type.
- PUT `/api/account/notification-preferences`
  - Body: UpdateNotificationPreferenceRequest.
  - Updates which channels are enabled for each notification event.

Step 6: Integration with login, MFA, consent and observability

Login and devices

- After a successful login, login pipeline must:
  - Call IDeviceService.RegisterOrUpdateDeviceAsync with:
    - TenantId, UserId
    - User agent, OS, browser, ip, country, device identifier.
  - If it is a new device:
    - Write an audit event "Account.Device.New".
    - In future phases, trigger notifications according to NotificationPreferences.

Sessions

- Ensure that every session created is trackable by ISessionOverviewService.
- The Account Center session APIs should use that service to show all active sessions and terminate them.

MFA

- The MFA related methods in IAccountSecurityService should be wrappers on the existing MFA module from Phase 3.
- Changing MFA configuration must:
  - Respect policy from Security and PolicyEngine (Phase 3 and 7).
  - Write appropriate audit events.

Consent and token issuance

- When user gives consent for an app during login:
  - Create or update UserConsent.
- During token issuance:
  - On each successful grant where a user token is issued:
    - Update LastUsedAt for that consent record (if consent model is in use).
- On revoke consent through Account Center:
  - Revoke refresh tokens and rely on existing access token expiry.

Observability and audit

- Use IAuditWriter to log all important account actions:
  - "Account.Profile.Updated"
  - "Account.PasswordChanged"
  - "Account.Mfa.Changed"
  - "Account.Device.Removed"
  - "Account.Device.New"
  - "Account.Sessions.Terminated"
  - "Account.Consent.Revoked"
  - "Account.RecoveryOptions.Updated"
  - "Account.NotificationPreferences.Updated"

These must show up in:
- Tenant Observability Activity view.
- User Activity page in Account Center.

Pages

2) Security page `/account/security`

Sections:

a) Change password

- Form:
  - Current password
  - New password
  - Confirm new password
- Show validation messages and password policy violations.
- Uses:
  - POST `/api/account/security/change-password`

b) MFA methods

- List of MfaMethodDto:
  - e.g. Authenticator App, SMS, Recovery codes.
- Actions:
  - Setup TOTP:
    - Call `/api/account/security/mfa/totp/setup` to get QR code and secret.
    - Show QR and secret.
    - User enters OTP to confirm via `/api/account/security/mfa/totp/confirm`.
  - Remove TOTP:
    - Call DELETE `/api/account/security/mfa/totp`.
  - Regenerate recovery codes:
    - Call `/api/account/security/mfa/recovery-codes/regenerate` and show them once.

3) Devices and sessions page `/account/devices-sessions`

Tabs:

Devices tab:
- Table displaying UserDeviceDto entries:
  - DeviceType with icon.
  - Os and Browser.
  - LastSeenAt.
  - LastIpAddress and LastCountry.
  - IsTrusted.
- Actions:
  - Remove device (call DELETE `/api/account/devices/{deviceId}`).
  - Remove all trusted devices (DELETE `/api/account/devices`).

Sessions tab:
- List UserSessionDto:
  - Device or user agent.
  - Location.
  - CreatedAt.
  - LastActivityAt.
  - Mark current session.
- Actions:
  - Sign out one session (DELETE `/api/account/sessions/{sessionId}`).
  - Sign out from all other sessions (DELETE `/api/account/sessions`).

4) Activity page `/account/activity`

- Shows list of UserActivityEntryDto from GET `/api/account/activity`.
- Columns:
  - Time.
  - Type (LoginSuccess, LoginFailed, PasswordChanged, MfaChanged, NewDevice etc).
  - Location.
  - Device or IP.
- Provide simple filters:
  - Date range.
  - Event type.

5) Apps and consents page `/account/apps-consents`

- List UserConsentDto:
  - ApplicationName.
  - ClientId.
  - GrantedScopes as badges.
  - GrantedAt.
  - LastUsedAt.
- Action:
  - Revoke access:
    - Confirmation modal.
    - Calls POST `/api/account/consents/{id}/revoke`.
    - After success, remove or mark consent as revoked and inform user that the app will require login and consent again.

6) Recovery and notifications page `/account/recovery-notifications`

Recovery options section:
- Shows email and phone from UserRecoveryOptionDto.
- Indicates whether each is verified.
- Allows updating:
  - Update recovery email or phone.
  - When changed, triggers a verification step:
    - show UI to enter OTP that was sent by email or SMS.
    - call dedicated verify endpoints if they exist or include in UpdateRecoveryOptions flow.

Notification preferences section:
- Table of NotificationEventType:
  - NewLogin.
  - NewDeviceTrusted.
  - PasswordChanged.
  - MfaChanged.
- For each event:
  - checkboxes or toggles for channels:
    - Email.
    - Sms.
    - InApp.
- Uses:
  - GET `/api/account/notification-preferences`
  - PUT `/api/account/notification-preferences`

All UI must use i18n and be accessible from both desktop and mobile.
