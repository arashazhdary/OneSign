High level goals of Phase 4
Phase 4 introduces:

- Federation module for:
  - SAML 2.0 IdP integration per tenant
  - OIDC based federation with external IdPs (Azure AD, Google Workspace, Okta, etc.)
  - Attribute mapping between external attributes and internal user, roles, org units
  - Just In Time (JIT) provisioning of users from external IdPs

- SCIM 2.0 provider for:
  - User provisioning and deprovisioning
  - Group provisioning mapped to roles or OrgUnits
  - Per tenant SCIM token

Step 4: Domain services – SAML, Federation login, attribute mapping, SCIM

Implement:

ISamlService

- Responsibilities:
  - Parse and validate SAML Responses
  - Validate signatures and certificates
  - Extract NameId and attributes
  - Generate SAML AuthnRequests for SP initiated flows

IFederationLoginService

- Responsibilities:
  - Handle SAML based login:
    - Locate tenant and SamlProvider
    - Use SamlApplicationBinding to find target ApplicationClient and tenant
    - Extract attributes via ISamlService
    - Apply attribute mappings via IAttributeMappingService
    - Perform JIT provisioning of GlobalUser and TenantUser if necessary
    - Pass the resulting tenant user context into the existing login/token issuance pipeline
  - Handle OIDC based login:
    - Call external OIDC provider using authority, clientId and clientSecret
    - After successful external auth, get claims
    - Map claims via IAttributeMappingService
    - Perform JIT provisioning if enabled
    - Pass user context to the main login pipeline

IAttributeMappingService

- Responsibilities:
  - For a given FederationType and tenant, load AttributeMapping definitions
  - Accept a dictionary of source attributes or claims and produce a structured result:
    - UserEmail
    - UserDisplayName
    - Roles (list)
    - OrgUnitCodes or identifiers
  - Apply simple TransformExpression functions described in the spec such as:
    - toLower()
    - split(';')[0]

IScimService

- Responsibilities:
  - Implement SCIM core operations:
    - Create, update, delete users and groups via the existing Identity and Organization modules
  - Map SCIM Users and Groups to:
    - GlobalUser and TenantUser
    - Roles and OrgUnits according to mappings
  - Produce SCIM compliant JSON responses and handle standard SCIM errors

All services must integrate with the existing Identity, Organization and Security modules, and must be fully implemented.

Step 7: API endpoints – Federation login and SCIM

Federation login endpoints:

SAML:

- POST `/saml/{tenantSlug}/acs`
  - Receives SAML Response from external IdP
  - Uses IFederationLoginService to handle login, including JIT provisioning
  - Finishes by issuing the same type of tokens as the main login pipeline, or redirecting to the application as required

- GET `/saml/{tenantSlug}/metadata`
  - Returns SAML metadata for onesign for that tenant, if required by the spec
  - Based on the tenant configuration and bindings

OIDC Federation:

- GET `/federation/oidc/{providerId}/signin`
  - Initiates OIDC login to the external IdP

- GET `/federation/oidc/{providerId}/callback`
  - Handles callback from external OIDC IdP
  - Uses IFederationLoginService to map attributes, JIT provision and complete login via the existing pipeline
