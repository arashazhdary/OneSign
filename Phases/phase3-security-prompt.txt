Step 4: Domain services – policies, MFA, device, risk

Implement:

ISecurityPolicyService

- GetPolicyForTenantAsync(tenantId)
- UpdatePolicyAsync(tenantId, newSettings)
- GetEffectiveMfaRequirementAsync(tenantUser, orgUnitsOfUser, isAdmin, deviceTrusted, riskLevel)

This service decides for a login:

- Whether MFA is required
- Whether login must be blocked based on RiskLevel and policy

IMfaService

- Generate TOTP shared secrets
- Verify TOTP codes
- Generate OTP for Email (and optionally SMS if configured)

IMfaChallengeService

- CreateMfaChallenge for a given TenantUser, MfaMethodType, device and ip
- Validate and consume a challenge plus code
- Enforce expiration and single use

IDeviceFingerprintService

- Resolve and manage TrustedDevice entities based on DeviceId
- When login with MFA completes and rememberDevice is set and allowed by policy, mark or create TrustedDevice with an expiry

IRiskEvaluationService

- Evaluate login attempts using device, IP and country
- Create RiskEvent entries for:
  - NewDeviceLogin
  - GeoAnomaly
  - MultipleFailedLogins
- Return a RiskLevel used by ISecurityPolicyService

All services must be fully implemented. No TODO or NotImplementedException.

Step 6: API endpoints – security policy, MFA, devices, risk

Add new endpoints in Onesign.Api as per the Phase 3 spec.

Tenant security policy and OrgUnit MFA rules:

Base `/api/tenant/security`

- GET `/api/tenant/security/policy`
  - Returns SecurityPolicyDto

- PUT `/api/tenant/security/policy`
  - Accepts UpdateSecurityPolicyRequest
  - Validates RememberDeviceDays, MaxFailedLoginAttempts and other fields
  - Writes to Audit

- GET `/api/tenant/security/org-units/mfa-rules`
  - Returns list of OrgUnitMfaRuleDto

- PUT `/api/tenant/security/org-units/mfa-rules`
  - Accepts UpdateOrgUnitMfaRulesRequest

Account MFA management:

Base `/api/account/mfa`

- GET `/api/account/mfa/methods`
  - Returns list of UserMfaMethodDto for the current tenant user

- POST `/api/account/mfa/totp/begin`
  - Request: BeginTotpEnrollmentRequest
  - Response: BeginTotpEnrollmentResponse with shared secret and otpauth url

- POST `/api/account/mfa/totp/confirm`
  - Request: ConfirmTotpEnrollmentRequest
  - Verifies TOTP and sets IsVerified = true

- POST `/api/account/mfa/methods/disable`
  - Request: DisableMfaMethodRequest
  - Enforces that at least one method remains if policy mandates MFA

Auth MFA login:

Update existing `POST /api/auth/login` to:

- If password is wrong:
  - behave exactly as before, including risk tracking for failed logins
- If password is correct:
  - Call ISecurityPolicyService and IRiskEvaluationService and DeviceFingerprintService to decide:
    - whether MFA is required
    - whether login must be blocked
  - If login is blocked due to risk:
    - return a localized or code based error
  - If MFA is not required:
    - complete login as Phase 1 and issue tokens
  - If MFA is required:
    - create an MfaChallenge
    - return a response indicating:
      - requiresMfa = true
      - challengeId
      - availableMethods

Add:

- POST `/api/auth/mfa/verify`
  - Request: VerifyMfaRequest (challengeId, methodType, code, deviceId, rememberDeviceFlag)
  - Uses IMfaChallengeService and IMfaService to validate code
  - On success:
    - completes login (issue tokens)
    - if rememberDeviceFlag and allowed by policy, create or update TrustedDevice
  - On failure:
    - updates risk data and returns localized or code based error

Account devices:

Base `/api/account/devices`

- GET `/api/account/devices`
  - Returns list of TrustedDeviceDto for current tenant user

- DELETE `/api/account/devices/{id}`
  - Removes a trusted device

Risk events:

Base `/api/tenant/security/risk-events`

- GET `/api/tenant/security/risk-events`
  - Accepts RiskEventFilterRequest via query string
  - Returns list of RiskEventDto with pagination if necessary

All endpoints must:

- Respect tenant context
- Respect localization
- Have proper error handling and use audit for sensitive changes
