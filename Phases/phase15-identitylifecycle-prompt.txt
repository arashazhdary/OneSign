Step 3: HR CSV Import and SCIM inbound
--------------------------------------------------

CSV Import

Implement endpoint:

- `POST /api/tenant/lifecycle/hr/csv-import`

Behavior:
- Accepts CSV file with columns:
  - EmployeeId (→ ExternalEmployeeId)
  - FirstName
  - LastName
  - Email
  - OrgUnitCode
  - JobRole
  - ManagerEmployeeId (→ ManagerExternalEmployeeId)
  - EmploymentStatus
  - StartDate
  - EndDate
- For each row:
  - Upsert HRIdentityRecord for this TenantId + ExternalEmployeeId:
    - Create new if not existing
    - Update existing if changed
    - Keep previous snapshot for comparison
  - Detect event type:
    - Joiner:
      - New record with EmploymentStatus Active and now within StartDate
      - Or previously non-active -> now Active
    - Mover:
      - Existing user with changed OrgUnitCode, JobRole, ManagerExternalEmployeeId, or critical attributes
    - Leaver:
      - EmploymentStatus becomes Terminated
      - Or EndDate passes current date
  - Create LifecycleEvent with:
    - EventType (Joiner/Mover/Leaver)
    - OldSnapshot, NewSnapshot
    - Status = Pending

- Return:
  - Count of processed rows
  - Count of Joiner/Mover/Leaver events created

SCIM inbound (minimal)

Implement SCIM `/scim/v2/Users` controller:

- Supported operations:
  - `POST /scim/v2/Users`
    - Map SCIM User to HRIdentityRecord
    - Create record and potentially JoinerEvent
  - `PUT or PATCH /scim/v2/Users/{id}`
    - Update HRIdentityRecord and detect Mover/Leaver
  - `DELETE /scim/v2/Users/{id}` or `PATCH active=false`
    - Mark HRIdentityRecord EmploymentStatus = Terminated and create LeaverEvent

Mapping:
- SCIM attributes:
  - `id` → ExternalEmployeeId
  - `userName` / `emails[0].value` → Email
  - `name.givenName`, `name.familyName`
  - `urn:ietf:params:scim:schemas:extension:enterprise:2.0:User.department` → OrgUnitCode
  - `title` → JobRole
  - `manager.value` → ManagerExternalEmployeeId
  - `active` → EmploymentStatus

Authentication:
- SCIM endpoints MUST be protected:
  - Use API key/mTLS or an auth method consistent with your platform.
- Do not leave them open.

Step 5: LifecycleProcessor – Joiner / Mover / Leaver
--------------------------------------------------

Implement `ILifecycleProcessor`:

- `Task ProcessEventAsync(LifecycleEvent @event)`

Joiner processing

- For a Joiner event:
  - If no TenantUser linked to ExternalEmployeeId:
    - Create or link GlobalUser (if your model uses it)
    - Create TenantUser for this tenant with:
      - Email, names from HRIdentityRecord
      - OrgUnit mapping via OrgHierarchy:
        - OrgUnitCode → OrgUnit
  - Evaluate policies:
    - `ILifecyclePolicyEvaluator.EvaluateAsync(hrRecord)`
  - For each AccessPackage:
    - Use Authorization/PolicyEngine to:
      - Assign roles to the TenantUser
    - Use Federation/SCIM outbound (existing module) to:
      - Provision access to applications in AccessPackage
  - Write audit events:
    - "Lifecycle.JoinerProcessed"
  - Use NotificationCenter:
    - Notify manager and/or SecurityOfficer if configured (e.g. "Lifecycle.JoinerCompleted")

Mover processing

- For a Mover event:
  - Load old and new HR snapshots.
  - Evaluate policies for old and new:
    - packagesOld, packagesNew
  - Compute:
    - toRemove = packagesOld \ packagesNew
    - toAdd = packagesNew \ packagesOld
  - For toRemove:
    - Revoke roles via Authorization/PolicyEngine
    - Trigger deprovision via Federation/SCIM for relevant apps
  - For toAdd:
    - Assign roles
    - Provision apps via Federation/SCIM
  - Audit:
    - "Lifecycle.MoverProcessed"
  - Optionally:
    - Call Governance module (Phase 10) for SoD checks:
      - If new access set violates SoD rules, log violation or mark for review.

Leaver processing

- For a Leaver event:
  - Disable TenantUser (and possibly GlobalUser if no other tenant membership):
    - Mark user as inactive/disabled in User module
  - Revoke live sessions and tokens:
    - Use existing session/token revocation mechanisms from Auth module.
  - Remove role assignments via Authorization/PolicyEngine.
  - Trigger outbound SCIM/Federation:
    - Disable or delete user from apps.
  - Audit:
    - "Lifecycle.LeaverProcessed"
  - Use NotificationCenter:
    - Inform manager/security if configured.

Step 6: Background worker / queue for LifecycleEvents
--------------------------------------------------

Implement a background worker / hosted service:

- Responsible for processing LifecycleEvents with Status = Pending.

Design:

- Poll periodically for a batch of Pending events:
  - Order by CreatedAt
  - Limit batch size for performance
- For each event:
  - Wrap ProcessEventAsync in try/catch
  - On success:
    - set Status = Processed
    - set ProcessedAt = now
  - On failure:
    - set Status = Failed
    - set ErrorMessage with truncated details
    - log error via Observability module

Make sure this worker is only registered once in the main API host environment and respects tenant isolation concerns.
