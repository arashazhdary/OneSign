- Add:
  - `RegionId` (string, not null)
  - `SecondaryRegionId` (string?, optional for future DR, but present in schema)

Migration:

- For existing tenants:
  - Set RegionId to a default region (e.g. "primary" or configured default).
- Enforce RegionId is required when creating new tenants.

Make sure RegionId is used consistently for:

- Resolving which DB cluster to use if you have per-region DB.

Create entity:

- `TenantDataResidencyPolicy`

  - DataRegionId (string)
  - BackupRegionId (string)
  - CrossRegionReplicationAllowed (bool)
  - ComplianceTag (string, e.g. "GDPR", "LocalReg", etc.)

Service:

- `ITenantDataResidencyService`
  - `Task<TenantDataResidencyPolicy?> GetAsync(Guid tenantId)`
  - `Task<TenantDataResidencyPolicy> UpsertAsync(TenantDataResidencyPolicy policy)`

Usage:

- Create default policy when a tenant is created:
  - DataRegionId = Tenant.RegionId.
  - BackupRegionId = same as DataRegionId unless configured otherwise.
- Enforce in backup/restore logic:
  - If CrossRegionReplicationAllowed == false:
    - RegionBackupSet and TenantBackupSet for that tenant must only reside in allowed regions.

APIs:

- Global scope:
  - `GET /api/global/tenants/{tenantId}/data-residency`
  - `PUT /api/global/tenants/{tenantId}/data-residency`
- Authorization:
  - Only Global Admin / SRE roles.

Step 5: Implement Tenant Restore
--------------------------------------------------

Service:

- `ITenantRestoreService`
  - `Task RestoreAsync(Guid tenantId, Guid backupSetId, string? targetRegionId = null)`

Logic:

- Load Tenant, BackupSet, TenantDataResidencyPolicy.
- Determine targetRegionId:
  - If targetRegionId is null → default to BackupSet.RegionId or Tenant.RegionId.
- Enforce policy:
  - If targetRegionId != policy.DataRegionId AND CrossRegionReplicationAllowed == false:
    - throw a domain/business exception (no silent cross region moves).

Restore process:

1) Put tenant into maintenance mode:
   - Use an existing maintenance flag or add one on Tenant:
     - e.g. `IsInMaintenanceMode`.
   - Prevent logins / token issuance for that tenant while restoring.

2) Clear current tenant data in target region:
   - For all multi-tenant tables containing TenantId:
     - delete or logically clear rows for that tenant in the target DB.

3) Use backup provider to restore:
   - Use TenantBackupSet.StorageLocation to retrieve snapshot.
   - Import into DB for that Region, only for that TenantId.

4) Exit maintenance mode:
   - Set `IsInMaintenanceMode = false`.

Audit events:

- "DR.TenantRestoreStarted"
- "DR.TenantRestoreCompleted"
- "DR.TenantRestoreFailed"

API:

- `POST /api/global/tenants/{tenantId}/restore`
  - body: { backupSetId, targetRegionId? }

Authorization:

- Only Global Admin / SRE.

Step 6: Implement Region Health & DR Runbook
--------------------------------------------------

Region health aggregation:

Service:

- `IRegionHealthService`
  - `Task<IReadOnlyList<RegionHealthDto>> GetRegionsHealthAsync()`

RegionHealthDto:

- RegionId
- Status (Healthy / Degraded / Down)
- LastSuccessfulBackupAt (from RegionBackupSet)
- TenantsCount
- CriticalAlertsCount (if you have an alerting integration; otherwise stub as 0 but keep property)

Status derivation (for now rule-based):

- Healthy:
  - last backup < threshold (e.g. 24h)
  - no recent critical errors
- Degraded:
  - last backup older than threshold OR some non-critical errors
- Down:
  - health checks failing or region marked down (you may integrate with health monitoring if present).

API:

- `GET /api/global/regions/health`
  - returns list of RegionHealthDto.

DR Runbook model:

Entity:

- `DRRunbookStep`
  - Id (Guid)
  - RegionId (string? – nullable for global steps)
  - Order (int)
  - Name (string)
  - Description (string)
  - ScriptReference (string, optional)

EF mapping:

- Table: `DR_RunbookSteps`
- Index: RegionId, Order.

Service:

- `IDRRunbookService`
  - `Task<IReadOnlyList<DRRunbookStep>> GetStepsForRegionAsync(string? regionId)`
  - `Task<DRRunbookStep> CreateOrUpdateAsync(DRRunbookStep step)` (Global Admin only)

Purpose:

- This is metadata only; no execution engine is required at this phase.
