Step 4: Implement Risk Scoring Engine
--------------------------------------------------

User Risk Score

Implement `IUserRiskScoringService`:

- Method:
  - `Task<UserRiskScore> CalculateAsync(UserAnalyticsSnapshot snapshot, UserRiskContext context)`
- `UserRiskScore`:
  - `int Score` (0–100)
  - `IReadOnlyList<RiskFactor>` Breakdown:
    - RiskFactor:
      - `Key` (e.g. "mfa_disabled", "privileged_roles", "failed_login_spike", "sod_violation", "zombie_access")
      - `DescriptionKey` (for i18n)
      - `WeightImpact` (positive number contributing to total)

Rule examples (implement them as concrete rules, not TODO):

- If MFAEnabled == false → +20
- If PrivilegedRolesCount > 0 → +25
- If FailedLoginCount in last 24h > threshold → +15
- If ActiveJitGrantsCount > 0 → +10
- If lastGovernanceReviewResult == Revoked or missing for long time → +10
- If lastLoginAt is older than N days, but user still has access packages / roles → +10 (Zombie-ish)
- If there exists open SoD findings for this user (from Governance) → +15

Implement all rules in code, use configuration for thresholds & weights:

- Put default weights in config (e.g. appsettings) so they are adjustable.

Tenant Risk Score

Implement `ITenantRiskScoringService`:

- Method:
  - `Task<TenantRiskScore> CalculateAsync(TenantAnalyticsSummary summary)`
- Factors:
  - Low MFAEnrollmentRate → higher risk
  - High number of HighRiskUsers (relative to UsersCount) → higher risk
  - Frequent BreakGlassUsage → higher risk
  - High number of OpenGovernanceFindings → higher risk

Score 0–100 with breakdown same pattern as user.

Scheduled risk calculation

- Background job:
  - For each UserAnalyticsSnapshot:
    - calculate UserRiskScore and attach to snapshot (fields Score + BreakdownJson).
  - For each TenantAnalyticsSummary:
    - calculate TenantRiskScore and persist.

Step 5: Insight generation engine
--------------------------------------------------

Implement `IInsightGenerationService`:

- Uses snapshots and risk scores to create/update/resolve `Insight` entities.

Insight types to implement now:

1) HighRiskUser

- Condition:
  - UserRiskScore > configurable threshold (e.g. 70).
- Behavior:
  - If no existing open HighRiskUser Insight for this user:
    - create new Insight:
      - Type = HighRiskUser
      - ScopeType = User
      - ScopeId = UserId
      - Severity based on score:
        - e.g. 70–80 → High, >80 → Critical.
      - Data: include risk factors for context.
  - If an existing open Insight exists and score drops below lower threshold:
    - mark Insight as Resolved.

2) ZombieAccount

- Condition:
  - LastLoginAt older than N days (e.g. 90 days),
  - but user still has roles/apps.
- Behavior:
  - Create Insight Type = ZombieAccount:
    - ScopeType = User
    - Severity:
      - higher if user has privileged role(s).
  - Resolve when user logs in or access is revoked.

3) ExcessivePrivileges

- Condition:
  - User roles/apps count >> median peers in same OrgUnit / JobRole.
  - Or roles/apps count passes a hard threshold.
- Behavior:
  - Create Insight Type = ExcessivePrivileges:
    - ScopeType = User
    - Data: list of high-impact roles/apps.
  - Resolve when roles are scaled down.

Optional:
- TenantHighRisk:
  - from TenantRiskScore.

Insight lifecycle

- New insights created when conditions first detected.
- Regular re-evaluation:
  - If condition no longer holds, mark insights as Resolved.
- Status transitions:
  - Open → Resolved / Dismissed (by admin).

Implement repository and APIs:

- `GET /api/tenant/insights`
  - filters: type, severity, status, date range, search.
- `GET /api/tenant/insights/{id}`
- `POST /api/tenant/insights/{id}/resolve`
- `POST /api/tenant/insights/{id}/dismiss`

Authorization: restricted to TenantAdmin / SecurityOfficer.
