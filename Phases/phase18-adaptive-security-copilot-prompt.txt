Step 2: Implement Adaptive Security models and services
--------------------------------------------------

Create or extend a security module, for example:
- `Onesign.Modules.SecurityAdaptive`

Inside it implement:

1) RiskBasedAuthPolicy model and storage

- Entity:
  - RiskBasedAuthPolicy:
    - TenantId
    - Enabled
    - MinRiskScoreForMfa
    - MinRiskScoreForStepUp
- EF mapping:
  - Table with TenantId as key or part of the key.
- Service:
  - `IRiskBasedAuthPolicyService`
    - `Task<RiskBasedAuthPolicy?> GetForTenantAsync(Guid tenantId)`
    - `Task<RiskBasedAuthPolicy> UpsertAsync(RiskBasedAuthPolicy policy)`

2) RiskBasedSessionPolicy model and storage

- Entity:
  - RiskBasedSessionPolicy:
    - TenantId
    - DefaultSessionLifetimeMinutes
    - HighRiskMaxSessionLifetimeMinutes
    - HighRiskIdleTimeoutMinutes
- EF mapping and migration.
- Service:
  - `IRiskBasedSessionPolicyService`
    - `Task<RiskBasedSessionPolicy?> GetForTenantAsync(Guid tenantId)`
    - `Task<RiskBasedSessionPolicy> UpsertAsync(RiskBasedSessionPolicy policy)`

3) AdaptiveAuthEvaluator

- Interface:
  - `IAdaptiveAuthEvaluator`
    - `Task<AdaptiveAuthDecision> EvaluateAsync(AdaptiveAuthContext context)`
- AdaptiveAuthContext:
  - TenantId
  - UserId
  - UserRiskScore (from IdentityInsights)
  - Relevant Insights for user (e.g. Compromised, UnderInvestigation etc if present)
  - RiskBasedAuthPolicy
- AdaptiveAuthDecision:
  - RequireMfa (bool)
  - RequireStepUp (bool)
  - BlockLogin (bool)
  - ReasonCodes (list of strings or enum keys, example:
    - "RISK_SCORE_HIGH"
    - "COMPROMISED_ACCOUNT"
    - "MFA_REQUIRED_BY_POLICY"
    - "CRITICAL_RISK_BLOCK"
  )

Implementation rules:
- If there is an explicit insight indicating account compromised or similar:
  - BlockLogin = true, with reason code.
- Else, if RiskScore >= MinRiskScoreForStepUp:
  - RequireStepUp = true, RequireMfa = true.
- Else, if RiskScore >= MinRiskScoreForMfa:
  - RequireMfa = true.
- Else:
  - no extra MFA requirements.

4) AdaptiveSessionConfigurator

- Interface:
  - `IAdaptiveSessionConfigurator`
    - `AdaptiveSessionConfig GetConfig(UserRiskScore riskScore, RiskBasedSessionPolicy policy)`
- AdaptiveSessionConfig:
  - SessionLifetimeMinutes
  - IdleTimeoutMinutes

Implementation rules:
- If riskScore.Score >= a high risk threshold (configurable):
  - SessionLifetimeMinutes = min(policy.DefaultSessionLifetimeMinutes, policy.HighRiskMaxSessionLifetimeMinutes)
  - IdleTimeoutMinutes = policy.HighRiskIdleTimeoutMinutes
- Otherwise:
  - SessionLifetimeMinutes = policy.DefaultSessionLifetimeMinutes
  - IdleTimeoutMinutes = default or global defaults.

Add logging and audit for adaptive decisions where appropriate.

Step 3: Integrate AdaptiveAuth into login pipeline
--------------------------------------------------

Modify the authentication / OIDC login pipeline:

- After verifying user credentials and before finalizing login:
  - Load:
    - UserRiskScore (from IdentityInsights module)
    - RiskBasedAuthPolicy (from SecurityAdaptive)
    - Relevant Insights for the user if needed.
  - Build AdaptiveAuthContext and call:
    - `IAdaptiveAuthEvaluator.EvaluateAsync(context)`

Behavior:
- If decision.BlockLogin:
  - Reject login with a clear error code (for client side handling).
  - Write audit event:
    - "AdaptiveSecurity.LoginBlockedByRisk" with:
      - TenantId, UserId, Score, ReasonCodes.
- If decision.RequireMfa or RequireStepUp:
  - Trigger the MFA or step up path in the login flow:
    - For example, mark in session state that MFA step is mandatory.
  - Write audit event:
    - "AdaptiveSecurity.RiskBasedMfaEnforced" with context.

This integration must be fully functional and not stubbed.

Step 4: Integrate AdaptiveSessionConfigurator into session issuance
--------------------------------------------------

In the part of the system that issues sessions and tokens:

  - Load:

    - RiskBasedSessionPolicy
  - Call:

- Use the returned SessionLifetimeMinutes and IdleTimeoutMinutes to configure:
  - cookie expiration

Write an audit event when session is hardened for risk:
- "AdaptiveSecurity.SessionHardened" with:
  - TenantId
  - UserId
  - RiskScore
  - New lifetime and idle timeout.

Step 5: Implement Recommendation engine
--------------------------------------------------

Create Recommendation entity and repository in a relevant module, for example:
- `Onesign.Modules.SecurityAdaptive` or `Onesign.Modules.IdentityInsights` if you prefer analytics centric.

Entity Recommendation:
- Id
- TenantId
- Type (string or enum, examples:
  - "MfaCoverage"
  - "ZombieCleanup"
  - "ExcessivePrivileges"
- ScopeType (Tenant, OrgUnit, User)
- ScopeData (json with list of user ids, orgunit ids etc)
- EstimatedImpactUsers (int)
- EstimatedImpactApps (int or optional)
- Status (Open, Applied, Dismissed)
- CreatedAt
- UpdatedAt

RecommendationGenerator service:
- `IRecommendationGenerator`
  - `Task GenerateOrUpdateAsync(Guid tenantId)`

Rules:
- MfaCoverageRecommendation:
  - Use TenantAnalyticsSummary and UserRiskScores from IdentityInsights:
    - If MFAEnrollmentRate is below a threshold:
      - Propose enabling or enforcing MFA for a segment:
        - for example HighRiskUsers with MFA disabled or a specific OrgUnit.
- ZombieCleanupRecommendation:
  - Use ZombieAccount insights (Phase 17):
    - For open ZombieAccount insights, group users and propose batch disable or access revocation.
- ExcessivePrivilegesRecommendation:
  - Use ExcessivePrivileges insights:
    - Suggest campaigns or bulk operations to reduce specific high impact roles.

APIs:
- `GET /api/tenant/security/recommendations`
  - Filters: type, status.
- `POST /api/tenant/security/recommendations/{id}/dismiss`
- `POST /api/tenant/security/recommendations/{id}/approve`

Approval:
- Can optionally create one or more SuggestedAction entries that can be executed later.

All APIs must enforce Authorization (SecurityOfficer / TenantAdmin only).

Step 6: Implement Security Copilot backend
--------------------------------------------------

Create a module:
- `Onesign.Modules.SecurityCopilot`

1) AiAdvisorClient abstraction

Define:
- `IAiAdvisorClient`
  - `Task<SecurityCopilotResponse> AskAsync(SecurityCopilotPrompt prompt)`

SecurityCopilotPrompt:
- NaturalLanguageQuery
- TenantContext:
  - TenantId
  - Locale
  - Optional time window
- DataContext:
  - summarized data from:
    - IdentityInsights (risk scores, insights)
    - PrivilegedAccess (JIT grants, privileged sessions)
    - Governance (open findings, campaigns)
    - Recommendations (existing open recommendations)

SecurityCopilotResponse:
- SummaryText
- KeyRisks (list of items with title and description)
- SuggestedActions (list of structured SuggestedActionDraft):
  - ActionType
  - ScopeData (user ids, orgunits etc)
  - TextDescription
  - EstimatedImpact

You do not implement the actual LLM integration here if the platform already has a shared AI client. Instead, wire to the existing one if there is. If not, implement a proper adapter that is ready to be hooked to an AI provider, but do not leave it empty. Use at least a deterministic stub that builds simple recommendations from existing data for now, with a clear extension point.

2) SecurityCopilotController

Implement API:
- `POST /api/tenant/security-copilot/query`

Steps:
- Validate that caller is SecurityOfficer or TenantAdmin.
- Parse the request:
  - Natural language query string.
- Build TenantContext (TenantId, locale).
- Build DataContext:
  - Query existing services:
    - IdentityInsights for top high risk users and insights.
    - PrivilegedAccess for privileged sessions and JIT grants.
    - Governance for open findings.
    - Recommendations for open recommended actions.
- Call `IAiAdvisorClient.AskAsync(prompt)`.
- Map SecurityCopilotResponse to DTO for the client:
  - summary, key risks, suggested action drafts.

3) SuggestedAction entity and execution

Create SuggestedAction entity:

- Id
- TenantId
- Origin (Copilot, RecommendationEngine)
- ActionType
- ScopeData (json structure, for example:
  - userIds: [...]
  - orgUnitIds: [...]
  - roleIds: [...]
- PreviewImpact (int counts)
- Status (Pending, Executed, Cancelled)
- CreatedAt
- ExecutedAt

When AiAdvisorClient returns SuggestedActionDrafts, persist them as SuggestedAction records with Status = Pending.

API for execution:

- `POST /api/tenant/security-copilot/actions/{id}/execute`

Behavior:
- Load SuggestedAction.
- Verify:
  - TenantId matches caller.
  - Caller is SecurityOfficer or TenantAdmin.
- Map ActionType to real operations:
  - Example:
    - EnforceMfaForUsers:
      - call Security module to enforce MFA or remove exemptions for given users.
    - DisableUsers:
      - call Lifecycle / User module to disable accounts.
    - DowngradeRoles:
      - call Authorization module to remove roles.
    - StartAccessReviewCampaign:
      - call Governance module to create a campaign for selected users.
- After success:
  - Mark SuggestedAction.Status = Executed.
  - Set ExecutedAt.
  - Write audit:
    - "SecurityCopilot.ActionExecuted" with full context.

Do not leave SuggestedAction with a no op execution path.
