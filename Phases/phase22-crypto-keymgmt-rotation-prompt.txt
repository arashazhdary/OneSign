Core model:

  - ActivatedAt

  - Purpose
  - RotationPeriodDays
  - OverlapPeriodDays
  - Enabled

  - Exactly ONE Active key for signing.
  - Zero or more Passive keys for validation of older tokens.
- Key generation:
  - New KeyVersion with fresh keypair and new kid.
- JWKS:
  - Includes Active + Passive public keys only.
- Token signing:
  - Always uses Active KeyVersion (by scope+purpose), sets kid in token header.

Rotation:
- Policy per (ScopeType, ScopeId, Purpose).
- Background job:
  - If now >= Active.ActivatedAt + RotationPeriodDays:

    - Previous Active → Passive with ExpiredAt = now + OverlapPeriodDays
    - Older Passive beyond overlap → Retired.

Manual operations:
- Rollover:
  - API to manually create a new Active version and demote old Active to Passive.
- Revoke:
  - Mark a KeyVersion as Revoked.
  - If revoking Active:
    - Optionally auto-create new Active.

UI:
- Global Crypto dashboard:
  - List KeySets
  - Inspect KeyVersions
  - Trigger manual rollover
  - Trigger revoke
- Rotation policy UI:
  - View + edit rotation policies.

Step 4: Wire token signing and validation to use KeySet/KeyVersion
--------------------------------------------------

In the token issuance pipeline:

1) Replace static keys with Crypto services:

- Before signing token:
  - Determine scope:
    - For now, use Environment-scoped signing:
      - scopeType = "Environment"

      - purpose = "OidcSigning"

  - Set `kid` in JWT header = KeyVersion.Kid.

2) Validation:

- For internal validation:
  - Use IKeyStore.GetPublicKeyAsync for relevant versions.
  - Or reuse JWKS building logic internally.
- For external clients:
  - They will call JWKS endpoint to get public keys.

Ensure:
- No static “signingKey” remains in config being used by TokenService.
- All signing flows are using KeySet-based keys.

Step 5: Implement JWKS endpoint
--------------------------------------------------

Create controller, e.g. `JwksController`:

Route:
- `/oidc/.well-known/jwks.json` for environment-level.
(If you already support per-tenant discovery, you can extend in future; for Phase 22 basic environment-level is fine.)

Behavior:

- Determine scope:
  - Environment-level: current EnvironmentId.
- Use `IKeySetService.GetPublicVersionsAsync("Environment", envId, "OidcSigning")` to get all KeyVersions with State ∈ {Active, Passive}.
- Convert each KeyVersion to JWK:

  - kty = "RSA" or "EC"
  - alg = Algorithm (RS256, ES256, etc.)
  - kid = KeyVersion.Kid
  - use = "sig"
  - key-specific parts:
    - RSA: n, e
    - EC: crv, x, y

- Build `{"keys": [ ... ]}` JSON.
- Add caching headers (e.g. short Cache-Control or ETag) to avoid spamming.

Make sure:
- Revoked and Retired states are NOT returned in JWKS.

Step 6: Implement rotation policy and scheduled rotation job
--------------------------------------------------

1) Rotation policy service

Define `IRotationPolicyService`:

- `Task<KeyRotationPolicy?> GetPolicyAsync(string scopeType, string scopeId, string purpose)`
- `Task<KeyRotationPolicy> UpsertPolicyAsync(KeyRotationPolicy policy)`
- `Task<IReadOnlyList<KeyRotationPolicy>> GetAllPoliciesAsync()`

2) Rotation job

Create background job `KeyRotationJob`:

- Periodically (e.g. once per day):
  - Fetch all enabled KeyRotationPolicies.
  - For each:
    - Resolve KeySet (ScopeType, ScopeId, Purpose).
    - Get Active KeyVersion.
    - If Active.ActivatedAt + RotationPeriodDays <= now:
      - Generate new keypair via IKeyStore.
      - Create new KeyVersion:
        - State = Active
        - ActivatedAt = now
      - Old Active:
        - Set State = Passive
        - Set ExpiredAt = now + OverlapPeriodDays
      - Any Passive that ExpiredAt <= now:
        - Set State = Retired.

3) Logging & audit:

- On each rotation:
  - Log with clear message.
  - Emit audit event: "Crypto.KeyVersion.Rotated" with:
    - ScopeType, ScopeId, KeySetId, OldKid, NewKid.

Step 7: Implement manual rollover and emergency revoke APIs
--------------------------------------------------

1) Manual rollover

Service:

- `IKeyRolloverService`
  - `Task<KeyVersion> RolloverAsync(Guid keySetId, string algorithm)`

Behavior:

- Load KeySet and Active KeyVersion.
- Generate new keypair with same algorithm or provided algorithm.
- Create new KeyVersion:
  - State = Active
  - ActivatedAt = now
- Active old:
  - State = Passive
  - ExpiredAt = now + defaultOverlap (e.g. from policy or config).
- Audit:
  - "Crypto.KeyVersion.Rotated" with actor info.

API:

- `POST /api/global/crypto/keysets/{keySetId}/rollover`
  - Body: optional algorithm.
  - Permissions: Global Admin / SecurityOfficer.

2) Emergency revoke

Service:

- `IKeyRevocationService`
  - `Task RevokeAsync(Guid keyVersionId, bool autoCreateNewActive)`

Behavior:

- Load KeyVersion.
- Set State = Revoked.
- If autoCreateNewActive == true and revoked key was Active:
  - Call Rollover for KeySet to create new Active key.
- JWKS must not return Revoked key.

API:

- `POST /api/global/crypto/keyversions/{id}/revoke`
  - Body: { autoCreateNewActive: bool }
  - Permissions: Global Admin / SecurityOfficer.
  - Show big warning in UI before calling.
