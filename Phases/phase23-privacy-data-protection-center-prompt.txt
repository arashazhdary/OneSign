Step 2: Implement DataRetentionCleanupJob
--------------------------------------------------

Create background job: `DataRetentionCleanupJob`.

Behavior:

- Periodically (e.g. daily):
  - For each tenant:
    - Load tenant’s DataRetentionPolicies.
    - For each category with Enabled=true:
      - Compute cutoff = now - RetentionPeriodDays.
      - Apply cleanup to corresponding tables:

    Examples (implement concretely in your codebase):

    - AuthEvents:
      - Table storing login/logoff/MFA events.
      - If HardDeleteAfter=true:
        - DELETE rows where TenantId = currentTenant AND EventTime < cutoff.
      - Else:
        - Anonymize user-related columns:
          - UserId → null or hashed ID
          - Username/Email (if stored) → null or generic.
          - Keep event time, result, technical info.

    - AuditLogs / FederationLogs / AccessRequests / LifecycleHistory:
      - Similar pattern: delete or anonymize user identifiers and PII, retain minimal technical metadata if HardDeleteAfter=false.

- Result:

  - Aggregate counts per tenant/category.
  - Emit an audit event:
    - "Privacy.RetentionCleanupExecuted"
    - with tenantId, category, deletedCount, anonymizedCount, timestamp.

No fake implementation:
- The job must actually modify data in DB.
- Use async EF operations and batch operations where possible.

Step 5: Implement Export execution
--------------------------------------------------

Service:

- `IDataExportService`
  - `Task<string> ExportUserDataAsync(Guid tenantId, string subjectId, Guid dsrId)`

Behavior:

- Within tenant scope:
  - Collect data for that subject from relevant modules:
    - Identity/Profile:
      - user record, claims, roles, org units (if present).
    - AuthEvents:
      - login/logout/MFA events for that user.
    - AccessRequests:
      - access requests submitted by that user.
    - LifecycleHistory:
      - joiner/mover/leaver events for that subject.

- Build export package:

  - Directory-like structure in memory, e.g.:
    - profile.json
    - auth-events.json
    - access-requests.json
    - lifecycle.json
  - Serialize to JSON for each part.
  - Bundle into a ZIP archive.

- Store:

  - Store ZIP in your object storage (MinIO/S3/whatever you use).
  - Generate a signed URL or temporary token (with expiry, e.g. 7 days).
  - Return that URL or storage path.

API to execute Export:

- `POST /api/tenant/privacy/data-requests/{id}/execute`

Behavior:

- Load DSR and validate:
  - Type == "Export"
  - Status in { "Requested", "InReview", "Approved" }.
- Set Status = "Processing".
- Call `IDataExportService.ExportUserDataAsync`.
- On success:
  - Set Status = "Completed".
  - Set ResultLocation = generated URL.
  - Set CompletedAt = now.
- Emit audit event "Privacy.DSR.ExportExecuted" with tenantId, subjectId, dsrId.

Permissions:

- Tenant DPO / SecurityOfficer only.

End user consumption:

- Later, Account Center will call `GET /api/account/privacy/data-requests` and read ResultLocation for completed exports.

Step 6: Implement Delete/Anonymize execution
--------------------------------------------------

Service:

- `IDataDeletionService`
  - `Task ExecuteDeleteAsync(Guid tenantId, string subjectId, Guid dsrId)`

Behavior:

- For the given tenant + subject:

  - User profile:
    - If business allows full deletion:
      - Delete or logical delete user record.
    - Otherwise anonymize:
      - Name → "Deleted User" (or localized i18n key).
      - Email → generated non-real value (hash + fixed domain).
      - Phone / address / other PII → null or generic.
      - Remove any personal identifiers not required for audit.

  - AuthEvents / AuditLogs / FederationLogs / AccessRequests / LifecycleHistory:
    - Replace direct references to the user with anonymized identifiers if needed:
      - UserId → hashed id (e.g. SHA-256 under a tenant-specific salt) or null.
      - Display/email fields → removed or generic.

- Ensure:
  - No foreign keys break.
  - No tokens or active sessions exist for that user (optional: revoke sessions as part of this).

API to execute Delete:

- `POST /api/tenant/privacy/data-requests/{id}/execute` when Type="Delete"

Behavior:

- Load DSR and validate:
  - Type == "Delete"
  - Status in { "Requested", "InReview", "Approved" }.
- Set Status = "Processing".
- Call `IDataDeletionService.ExecuteDeleteAsync`.
- On success:
  - Status = "Completed"
  - CompletedAt = now.
- Emit audit event "Privacy.DSR.DeleteExecuted".

Permissions:

- Tenant DPO / SecurityOfficer only.

Also implement:

- Option to mark DSR as Rejected:
  - `POST /api/tenant/privacy/data-requests/{id}/reject`
    - body: { reason }
  - Status = "Rejected"
  - Reason stored.
