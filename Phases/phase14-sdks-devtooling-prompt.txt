Step 3: Node SDK - @onesign/sdk-node
--------------------------------------------------

Create a Node package project:

- `sdk-node/` or `src/sdk-node/`

Package name:

- `@onesign/sdk-node`

Structure:

- `src/authMiddleware.ts`
- `src/discovery.ts`
- `src/jwksCache.ts`
- `src/index.ts`

Implement OIDC discovery helper

- `async function discoverOpenIdConfig(authority: string): Promise<OpenIdConfig>`
  - Fetch `${authority}/.well-known/openid-configuration`
  - Parse jwks_uri and other relevant fields
  - Cache result in memory with TTL

Implement JWKS cache helper

- `async function getJwks(authority: string): Promise<Jwks>`
  - Uses discovered jwks_uri
  - Fetch JWKS
  - Cache keys
  - Provide a way to find the proper public key for a given token kid

Implement auth middleware

- `function createOnesignAuthMiddleware(config: { authority: string; audience: string; })`
  - Returns an Express compatible middleware `(req, res, next)`
  - Behavior:
    - Read `Authorization` header
    - Extract bearer token
    - Validate token:
      - Use JWKS for signature
      - Check issuer (matches authority)
      - Check audience
      - Check exp and nbf
    - On success:
      - Attach decoded claims to `req.user`
      - Extract and attach `req.tenantId` from claims if present
      - Call `next()`
    - On failure:
      - Respond with 401 or 403 and a structured error

Implement sample Express app

- In `samples/node-api`:
  - Express server with:
    - `app.use(createOnesignAuthMiddleware(config))`
    - `GET /api/secure` endpoint that returns `req.user` and `req.tenantId`
- README with:
  - How to install the package
  - How to configure authority and audience
  - How to run and test against onesign

Step 6: CLI - onesign-cli
--------------------------------------------------

Create CLI project

- Technology:
  - You may use .NET global tool or Node based CLI. Choose one consistent with your stack.
- Name:
  - `onesign-cli`

Configuration

- CLI needs to:
  - Store auth tokens locally (for tenant admin) in a config file or keyring
  - Target sandbox or production endpoints

Command: `onesign login`

- Performs authentication as a tenant admin or developer:
  - For example with device code flow or browser based login
- Stores:
  - Access token
  - Tenant id
  - API endpoint

Command: `onesign apps list`

- Calls DevPortal or tenant app management API:
  - Lists application clients for current tenant
- Output:
  - id, name, type, redirectUris count

Command: `onesign apps create`

- Parameters:
  - name
  - type (confidential or public)
  - redirectUri list
- Creates a new ApplicationClient in onesign
- Returns:
  - clientId
  - clientSecret (if confidential)
- Prints config hints

Command: `onesign apps update-redirects`

- Updates redirect URIs for an existing app

Command: `onesign apps generate-config`

- Parameters:
  - `--app <id>`
  - `--format dotnet|node|react`
- Behavior:
  - Fetches app metadata and tenant authority
  - Prints a ready to paste snippet:
    - For dotnet:
      - appsettings.json section
    - For node:
      - .env lines: ONESIGN_AUTHORITY, ONESIGN_AUDIENCE
    - For react:
      - env lines: VITE_ONESIGN_AUTHORITY, VITE_ONESIGN_CLIENT_ID, VITE_ONESIGN_REDIRECT_URI

Implementation details

- CLI uses HTTPS calls to onesign management APIs, consistent with DevPortal from previous phases:
  - For example:
    - `/api/tenant/devportal/apps/*` or similar endpoints

- Do not fake CLI functionality:
  - All commands must actually call real APIs or stably designed internal endpoints
