CONCEPTS – WHAT YOU MUST BUILD
==================================================

Phase 26 introduces:

1) **AutomationWorkflow**
   - A playbook describing:
     - Triggers (which events)
     - Conditions (when)
     - Actions (what to do)

2) **Triggers**
   - Which events fire the workflow.
   - Examples:
     - `Auth.SignInSucceeded`
     - `Auth.SignInFailed`
     - `Auth.HighRiskSignInDetected`
     - `AccessRequest.Created`
     - `AccessRequest.Approved`
     - `Lifecycle.LeaverDetected`
     - `PrivilegedAccess.BreakGlassUsed`
     - `Insights.TenantRiskScoreHigh`

3) **Conditions**
   - Boolean rules on event payload fields:
     - `riskScore >= 80`
     - `user.mfaEnabled == false`
     - `location.country IN ["US","GB","DE"]`
   - Implemented via a small JSON-based expression (JsonLogic-style).

4) **Actions**
   - Internal security actions:
     - RevokeSessions(userId)
     - RequireMfaNextSignIn(userId)
     - LockUserAccount(userId)
     - DisableAppAccess(userId, appId)
     - TriggerAccessReview(appId or orgUnit)
   - Notification actions:
     - SendEmail(to, templateId, data)
     - SendToChannel (Slack/Teams/Webhook)
   - Extensibility actions:
     - InvokeWebhook(url, payload)
     - PushEventToQueue(topic, message)

5) **Execution logs**
   - AutomationExecution records:
     - which workflow ran
     - for which event
     - what actions ran
     - which ones failed and why

6) **Global templates vs tenant workflows**
   - Global Admin defines templates as best practices.
   - Tenants can:
     - clone templates into their own workflows
     - sometimes customize them (if allowed)
   - Some templates may be “enforced” globally.

{
  "all": [

    { "in": [ { "var": "location.country" }, ["US", "GB", "DE"] ] }

- ActionType (string)          // "RevokeSessions", "SendEmail", "InvokeWebhook", ...

Table: `Automation_Actions`.

5) AutomationExecution

- Id (Guid)
- WorkflowId (Guid, FK)
- TenantId (Guid)
- EventType (string)
- EventId (string?)            // optional if event has an id
- StartedAt (DateTimeOffset)
- CompletedAt (DateTimeOffset?)
- Status (string)              // "Pending", "Running", "Succeeded", "Failed", "Skipped"
- ErrorMessage (string?)
- ActionsExecutedCount (int)
- ActionsFailedCount (int)
- PayloadSnapshot (string)     // sanitized payload summary

Table: `Automation_Executions`.

You must:

Implement a reusable condition evaluator:

- Input:

  - "app.id"

2) Action handlers

Implement action execution service(s) that:

- For each AutomationAction, based on ActionType:
  - Parse ConfigJson
  - Call the right dependency/module
  - Return a result (success/failure, optional message)

MANDATORY internal actions to implement:

- `RevokeSessions(userId)`
  - Integrate with existing Auth/Session store to invalidate all current sessions for the user in this tenant.

- `RequireMfaNextSignIn(userId)`
  - Integrate with AdaptiveSecurity/Auth to enforce MFA on next login (set appropriate flag/requirement for this user).

- `LockUserAccount(userId)`
  - Call Identity module to lock the user's account.

- `DisableAppAccess(userId, appId)`
  - Call Authorization/App assignment module to remove or disable that user's access to a specific app.

MANDATORY notification/extension actions:

- `SendEmail`
  - Use NotificationCenter:
    - TemplateId
    - Recipients
    - Data (variables from event payload)
  - Must actually send email.

- `InvokeWebhook`
  - HTTP POST to the configured URL with:
    - event summary
    - workflow id
  - With timeout and error handling.

No “fake handlers” allowed. Every configured ActionType must have real effect.

BACKEND – EVENT BUS & AUTOMATION ENGINE
==================================================

1) EventBus subscription

Wire Automation module into the existing event publishing mechanism so it can receive events like:

- "Auth.SignInSucceeded"
- "Auth.SignInFailed"
- "Auth.HighRiskSignInDetected"
- "AccessRequest.Created"
- "AccessRequest.Approved"
- "Lifecycle.LeaverDetected"
- "PrivilegedAccess.BreakGlassUsed"
- "Insights.TenantRiskScoreHigh"

Assumptions:

- Each event payload contains at least:
  - TenantId
  - Maybe UserId, AppId, RiskScore, Location, Device, etc.

2) AutomationEngine

Implement a core service `IAutomationEngine` with something like:

- `Task HandleEventAsync(string eventType, object payload, string? eventId)`

Behavior:

- Determine tenant from payload.
- Fetch all active workflows that:
  - Match the eventType through their triggers.
  - Are either:
    - tenant-scoped workflows for that TenantId
    - global workflows/templates that are enforced for all tenants.

- For each such workflow:

  - Evaluate conditions (if any). If false:
    - Optionally log a "Skipped" execution or skip without creating a record.

  - If true:
    - Create AutomationExecution:
      - Status = "Running"
      - PayloadSnapshot = sanitized subset of payload (no full PII).
    - Execute actions in defined order:
      - For each action:
        - Run the handler.
        - Keep track of success/failure counts.
        - Respect IsCritical:
          - If a critical action fails, you may stop the chain and mark execution Failed.
    - At the end:
      - Set Status = "Succeeded" or "Failed".
      - Fill ActionsExecutedCount and ActionsFailedCount.
    - Persist execution record.

3) Idempotency & throttling

- Use (WorkflowId + EventId) to prevent double execution for the same event, if EventId is provided.
- Optionally enforce per-tenant rate limits if needed (at least keep the design extension point ready).
