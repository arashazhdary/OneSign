Step 4: Domain services – audit, alerts, log streaming

Implement:

IAuditWriter

- Responsible for writing audit events from all modules.
- Provide helpers to build events using the current context:

  - TenantId
  - Current user
  - IP, UserAgent
  - CorrelationId

- Methods like:

  - `Task WriteAsync(AuditEvent auditEvent);`
  - Optional convenience helpers: `WriteUserActionAsync`, `WriteSystemActionAsync`, etc.

AuditWriter implementation:

- Maps domain AuditEvent into AuditEventEntity.
- Uses AuditEventRepository to persist.
- Should be lightweight and non-blocking where possible.

IAuditQueryService

- Search API:

  - `Task<AuditSearchResultDto> SearchAsync(AuditSearchFilterDto filter, TenantScope scope…)`
  - Filter fields:
    - TenantId (for global search)
    - Date range
    - Category
    - Severity
    - ActorId / Actor email
    - Action
    - IpAddress / Country

- `Task<AuditEventDto> GetByIdAsync(Guid id);`

IAlertEvaluationService

- Logic for evaluating alert rules per tenant based on:

  - AuditEvents
  - Possibly RiskEvents / UsageCounters if needed.

- Methods like:

  - `Task EvaluateForTenantAsync(Guid tenantId, DateTime since);`

- Implement threshold-based alerts:

  - Example:

    - MetricKey: "Auth.LoginFailed"
    - Threshold: 20
    - Window: 10 minutes

  - Evaluate by querying recent AuditEvents and counting matching events.

- On trigger:

  - Create AlertNotificationEntity.
  - Dispatch to channels via AlertChannel configuration (email/webhook).

ILogStreamingService

- Responsible for pushing batches of AuditEvents to configured LogStreamSubscriptions.
- Methods:

  - `Task PushBatchAsync(LogStreamSubscription sub, IReadOnlyCollection<AuditEvent> events);`

- Behavior:

  - For each subscription:
    - Filter AuditEvents by category/severity.
    - Push in batches to TargetUrl as JSON.
    - Handle retries and simple backoff behavior on failure.

All services must be implemented fully. No stubs.

Step 9: Scheduled jobs – alerts and log streaming

Implement scheduled/background jobs:

Alert evaluation job:

- Periodic job (e.g. every 1–5 minutes):
  - For each tenant with enabled AlertRules:
    - Execute EvaluateAlertsForTenantCommand(tenantId, sinceLastCheck).

Log streaming job:

- Periodic job:
  - Fetch recent AuditEvents that have not been streamed yet.
  - Group them per LogStreamSubscription.
  - Execute PushAuditEventsToLogStreamCommand for each subscription.

Use a robust but simple mechanism to avoid double-sending:

- For example:
  - Track last streamed timestamp per subscription.
  - Or mark events once streamed for a given subscription.
