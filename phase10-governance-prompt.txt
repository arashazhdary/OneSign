Step 5: Domain services – Access Reviews
--------------------------------------------------

Implement IAccessReviewService

Responsibilities:
- Create/update/cancel campaigns.
- Retrieve campaigns and campaign details.

Methods example:
- CreateCampaignAsync(tenantId, CreateAccessReviewCampaignRequest)
- UpdateCampaignAsync(tenantId, campaignId, UpdateAccessReviewCampaignRequest)
- ScheduleCampaignAsync(tenantId, campaignId)
- CancelCampaignAsync(tenantId, campaignId)
- GetCampaignsAsync(tenantId, filter/paging)
- GetCampaignDetailsAsync(tenantId, campaignId)

Implement IAccessReviewExecutionService

Responsibilities:
- Execute campaign (generate AccessReviewItems).
- Manage status transitions: Draft → Scheduled → Running → Completed.

Methods example:
- RunCampaignNowAsync(tenantId, campaignId)
  - Validate campaign is in Draft or Scheduled.
  - Resolve scope:
    - For Type=ByApplication:
      - For each ApplicationClient in scope:
        - Get all users with access to that app (via Role/Policy assignments).
    - For Type=ByOrgUnit:
      - For each OrgUnit in scope:
        - Get users in that OrgUnit (via OrgHierarchy module).
        - For each user, get apps/roles they have.
    - For Type=ByRole:
      - For each role in scope:
        - Get all users with that role.
  - For each (user, app[, role]) combination:
    - Create AccessReviewItem with Pending status and resolved reviewer.
  - Set campaign.Status = Running or Completed depending on presence of items.

- Internal logic to determine reviewer:
  - ByOrgUnit:
    - Use OrgHierarchy (Phase 2) to find OrgUnit.Manager as reviewer.
  - ByApplication:
    - Use Application metadata to find AppOwner as reviewer.
  - ByRole:
    - Use role owner or fallback SecurityOfficer role.

Implement decision methods:

- ApproveItemAsync(itemId, reviewerUserId, reason)
  - Validate that reviewerUserId is allowed to review this item.
  - Set item.Status = Approved, ReviewedAt = now, DecisionReason = reason.
  - Write audit event "Governance.AccessReview.Approved".

- RevokeItemAsync(itemId, reviewerUserId, reason)
  - Validate reviewer.
  - Set item.Status = Revoked, ReviewedAt = now, DecisionReason = reason.
  - Call User/Role/Policy modules to remove user’s assignment to that app/role.
  - Write audit event "Governance.AccessReview.Revoked".

- EscalateItemAsync(itemId, reviewerUserId, reason)
  - Set item.Status = Escalated, ReviewedAt = now, DecisionReason = reason.
  - (In future phases, use Notification/Workflow – here just store status + audit.)

Implement ISoDService

Responsibilities:
- Manage SoD rules.
- Run SoD checks and create/update violations.
- Resolve violations.

Methods example:

- On violation resolution:

Step 7: Governance APIs under `/api/tenant/governance/*`
--------------------------------------------------

Base path: `/api/tenant/governance`

All these endpoints are tenant-scoped and require appropriate tenant roles:
- ComplianceOfficer
- SecurityOfficer
- TenantAdmin (where applicable)
- For reviewer actions, normal manager/app-owner users can call "my-items" endpoints.

Access Review Campaign API

- GET `/api/tenant/governance/access-reviews`
  - Returns paged list of AccessReviewCampaignDto for tenant.

- GET `/api/tenant/governance/access-reviews/{id}`
  - Returns AccessReviewCampaignDto + scope + stats.

- POST `/api/tenant/governance/access-reviews`
  - Body: CreateAccessReviewCampaignRequest.
  - Creates a new campaign in Draft.

- PUT `/api/tenant/governance/access-reviews/{id}`
  - Body: UpdateAccessReviewCampaignRequest.
  - Only allowed in Draft or Scheduled states.

- POST `/api/tenant/governance/access-reviews/{id}/schedule`
  - Moves campaign to Scheduled.

- POST `/api/tenant/governance/access-reviews/{id}/run-now`
  - Triggers IAccessReviewExecutionService.RunCampaignNowAsync.
  - Moves to Running/Completed depending on item generation.

- POST `/api/tenant/governance/access-reviews/{id}/cancel`
  - Allowed only for Draft or Scheduled.
  - Sets Status = Cancelled.

Review Items API

- GET `/api/tenant/governance/access-reviews/my-items`
  - Returns AccessReviewItemDto list assigned to current user as reviewer.
  - Supports paging and filtering by status.

- GET `/api/tenant/governance/access-reviews/{campaignId}/items`
  - For ComplianceOfficer role: list all items in a campaign.

- POST `/api/tenant/governance/access-reviews/items/{id}/approve`
  - Body can include reason.
  - Calls ApproveItemAsync.

- POST `/api/tenant/governance/access-reviews/items/{id}/revoke`
  - Calls RevokeItemAsync (which must trigger actual permission removal).

- POST `/api/tenant/governance/access-reviews/items/{id}/escalate`
  - Calls EscalateItemAsync.

SoD Rules and Violations API

- GET `/api/tenant/governance/sod/rules`
  - Returns list of SoDRuleDto.

- POST `/api/tenant/governance/sod/rules`
  - CreateSoDRuleCommand.

- PUT `/api/tenant/governance/sod/rules/{id}`
  - UpdateSoDRuleCommand.

- DELETE `/api/tenant/governance/sod/rules/{id}`

- POST `/api/tenant/governance/sod/run-check`
  - Triggers RunSoDCheckAsync for current tenant.

- GET `/api/tenant/governance/sod/violations`
  - Returns SoDViolationDto list with paging and filters (IsResolved, Severity, RuleId).

- POST `/api/tenant/governance/sod/violations/{id}/resolve`
  - Body with ResolutionNote.
  - Calls ResolveViolationAsync.

Export & Dashboard API

- POST `/api/tenant/governance/access-reviews/{id}/export`
  - Triggers GenerateExportAsync.
  - Returns GovernanceExportDto with export id.

- GET `/api/tenant/governance/exports`
  - List GovernanceExportDto for tenant.

- GET `/api/tenant/governance/exports/{id}/download`
  - Returns file download.

- GET `/api/tenant/governance/dashboard`
  - Returns GovernanceDashboardDto with:
    - Count of campaigns by status.
    - Percentage of items reviewed vs pending per recent campaigns.
    - Number of open SoDViolations.
    - Basic summary metrics.

Localization

    - Governance/Compliance-oriented endpoints → ComplianceOfficer/SecurityOfficer/TenantAdmin.

Performance

  - All list endpoints MUST implement paging.
  - Use the indexes described above.
- SoD checks:
  - Implement in batch manner:
    - Minimize N+1 queries when scanning users and roles.
  - Consider running via background job infrastructure if available (but implement the logic callable from a command).

Audit / Observability

- Use IAuditWriter to log:
  - Campaign lifecycle.
  - Item decisions.
  - SoD rule changes.
  - SoD violations.
  - Exports.
- Make sure these events show up in Observability views built in Phase 6.
